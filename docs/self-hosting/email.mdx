---
title: "Email"
description: "Configure email delivery so GitArena can send verification messages."
---

GitArena sends transactional emails for account verification. Without email delivery configured, verification emails aren't delivered and new accounts can't confirm their email addresses.

## How email delivery works

Outgoing emails are queued in the database using an async job queue (powered by [fang](https://github.com/ayrat555/fang)). A dedicated pool of two workers picks up queued messages and sends them over SMTP. This means email delivery is non-blocking — the HTTP request that triggers an email returns immediately, and the message is sent in the background.

Email templates are rendered server-side using [Askama](https://github.com/askama-rs/askama).

## SMTP configuration

GitArena connects to an SMTP server to send emails. Configure the connection in the `settings` table:

| Key             | Description                      | Example               |
|-----------------|----------------------------------|-----------------------|
| `smtp.enabled`  | Enable or disable email delivery | `true`                |
| `smtp.server`   | SMTP server hostname             | `smtp.resend.com`     |
| `smtp.port`     | SMTP server port                 | `587`                 |
| `smtp.username` | SMTP login username              | `resend`              |
| `smtp.password` | SMTP login password or API key   | `api_key`             |
| `smtp.address`  | From address for outgoing emails | `noreply@example.com` |
| `smtp.tls`      | Use implicit TLS                 | `false`               |

```sql
UPDATE settings SET value = 'true'                WHERE key = 'smtp.enabled';
UPDATE settings SET value = 'smtp.resend.com'     WHERE key = 'smtp.server';
UPDATE settings SET value = '587'                 WHERE key = 'smtp.port';
UPDATE settings SET value = 'resend'              WHERE key = 'smtp.username';
UPDATE settings SET value = 'your_api_key'        WHERE key = 'smtp.password';
UPDATE settings SET value = 'noreply@example.com' WHERE key = 'smtp.address';
UPDATE settings SET value = 'false'               WHERE key = 'smtp.tls';
```

### TLS selection

| `smtp.tls` | Protocol     | Use when                                         |
|------------|--------------|--------------------------------------------------|
| `false`    | Plain        | Avoid — blocked by most ISPs and cloud providers |
| `true`     | Implicit TLS | Require TLS from the start                       |

`STARTTLS` is not supported yet. Make your voice heard on the issue tracker if you want this feature.

## Email verification flow

When a user adds an email address (during registration or from account settings), GitArena:

<Steps>
  <Step title="Create a verification record">
    A row is inserted into the `user_verifications` table with a random hex token. The email send is queued in the job queue.
  </Step>
  <Step title="Send the verification email">
    The email worker picks up the queued task and sends an email containing a link: `https://your-instance/api/verify/{token}`.
  </Step>
  <Step title="User clicks the link">
    GitArena looks up the token, marks the email address as verified, and deletes the verification record. Tokens expire after 24 hours.
  </Step>
</Steps>

Users can request a new verification email from their account settings if the link has expired.

## Disabling email

Set `smtp.enabled` to `false` to disable outgoing email. Verification flows skip queueing new email tasks while SMTP is disabled. If an email task is already queued and no mail transport is configured, the worker exits without sending it.

<Note>
  If `smtp.enabled` is `false`, the remaining SMTP settings are ignored and do not need to be configured.
</Note>
