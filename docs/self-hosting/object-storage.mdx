---
title: "Object storage"
description: "Configure S3-compatible object storage for release asset uploads."
---

GitArena uses S3-compatible object storage to host release assets. Files upload directly from the browser to storage using presigned URLs — they do not pass through the GitArena process.

Any S3-compatible provider works: AWS S3, Cloudflare R2, Supabase Storage, MinIO, Garage, and others.

## Configuration

Set the following keys in the `settings` table:

| Key | Default | Description |
|-----|---------|-------------|
| `s3.enabled` | `false` | Enable object storage. Set to `true` to activate asset uploads. |
| `s3.bucket` | — | Bucket name to store assets in. |
| `s3.region` | — | Region the bucket is in, e.g. `us-east-1`. |
| `s3.access_key_id` | — | Access key ID for authentication. |
| `s3.secret_access_key` | — | Secret access key for authentication. |
| `s3.endpoint` | — | Custom endpoint URL for non-AWS providers, e.g. `https://your-project.supabase.co/storage/v1/s3`. Leave unset for AWS S3. |
| `s3.force_path_style` | `false` | Use path-style URLs (`endpoint/bucket/key`) instead of virtual-hosted-style (`bucket.endpoint/key`). Required for most non-AWS providers. |

```sql
UPDATE settings SET value = 'true'                           WHERE key = 's3.enabled';
UPDATE settings SET value = 'your-bucket'                    WHERE key = 's3.bucket';
UPDATE settings SET value = 'us-east-1'                      WHERE key = 's3.region';
UPDATE settings SET value = 'your-access-key-id'             WHERE key = 's3.access_key_id';
UPDATE settings SET value = 'your-secret-access-key'         WHERE key = 's3.secret_access_key';
UPDATE settings SET value = 'https://your.endpoint.example'  WHERE key = 's3.endpoint';
UPDATE settings SET value = 'true'                           WHERE key = 's3.force_path_style';
```

When `s3.enabled` is `false`, the remaining settings are not read and do not need to be set.

<Warning>
  When `s3.enabled` is `true`, all other `s3.*` settings except `s3.endpoint` are required. GitArena will fail to start if any of them are missing.
</Warning>

## Provider-specific notes

### AWS S3

Leave `s3.endpoint` unset and `s3.force_path_style` as `false`. Set `s3.region` to the region your bucket is in:

```sql
UPDATE settings SET value = 'true'         WHERE key = 's3.enabled';
UPDATE settings SET value = 'my-bucket'    WHERE key = 's3.bucket';
UPDATE settings SET value = 'eu-west-1'    WHERE key = 's3.region';
UPDATE settings SET value = 'AKIAIOSFODNN' WHERE key = 's3.access_key_id';
UPDATE settings SET value = 'wJalrXUtnFEM' WHERE key = 's3.secret_access_key';
```

### Cloudflare R2

R2 uses path-style URLs and a custom endpoint. Set `s3.force_path_style` to `true` and use your R2 endpoint:

```sql
UPDATE settings SET value = 'true'                                       WHERE key = 's3.enabled';
UPDATE settings SET value = 'my-bucket'                                  WHERE key = 's3.bucket';
UPDATE settings SET value = 'auto'                                       WHERE key = 's3.region';
UPDATE settings SET value = 'your-access-key-id'                         WHERE key = 's3.access_key_id';
UPDATE settings SET value = 'your-secret-access-key'                     WHERE key = 's3.secret_access_key';
UPDATE settings SET value = 'https://<account>.r2.cloudflarestorage.com' WHERE key = 's3.endpoint';
UPDATE settings SET value = 'true'                                       WHERE key = 's3.force_path_style';
```

### Supabase Storage

Supabase exposes an S3-compatible API. Use your project's S3 endpoint and set `s3.force_path_style` to `true`:

```sql
UPDATE settings SET value = 'true'                                              WHERE key = 's3.enabled';
UPDATE settings SET value = 'your-bucket'                                       WHERE key = 's3.bucket';
UPDATE settings SET value = 'us-east-1'                                         WHERE key = 's3.region';
UPDATE settings SET value = 'your-access-key-id'                                WHERE key = 's3.access_key_id';
UPDATE settings SET value = 'your-secret-access-key'                            WHERE key = 's3.secret_access_key';
UPDATE settings SET value = 'https://<project>.supabase.co/storage/v1/s3'      WHERE key = 's3.endpoint';
UPDATE settings SET value = 'true'                                              WHERE key = 's3.force_path_style';
```

### MinIO

Point `s3.endpoint` at your MinIO server and enable path-style access:

```sql
UPDATE settings SET value = 'true'                    WHERE key = 's3.enabled';
UPDATE settings SET value = 'gitarena'                WHERE key = 's3.bucket';
UPDATE settings SET value = 'us-east-1'               WHERE key = 's3.region';
UPDATE settings SET value = 'minioadmin'              WHERE key = 's3.access_key_id';
UPDATE settings SET value = 'minioadmin'              WHERE key = 's3.secret_access_key';
UPDATE settings SET value = 'http://minio:9000'       WHERE key = 's3.endpoint';
UPDATE settings SET value = 'true'                    WHERE key = 's3.force_path_style';
```

## Bucket permissions

The credentials you provide must have permission to:

- `s3:PutObject` — upload new assets
- `s3:GetObject` — read assets for SHA-256 computation and generating download URLs
- `s3:DeleteObject` — delete assets when a release or asset is removed

Restrict the credentials to the specific bucket used for GitArena assets.

## Object layout

Assets are stored under `releases/{releaseId}/{assetId}/{filename}`. The filename is preserved so that presigned download URLs carry the original file name.
