---
title: "CAPTCHA"
description: "Current status of hCaptcha settings and registration checks."
---

GitArena has backend-side hCaptcha settings and registration checks, but the current frontend integration is not complete.

<Warning>
  Do not enable hCaptcha on a production instance until the frontend widget and backend secret handling are verified together. When `hcaptcha.site_key` is set, registration requires an `h-captcha-response` field.
</Warning>

## Settings

The settings table contains these keys:

| Key | Description |
|-----|-------------|
| `hcaptcha.enabled` | Feature flag for hCaptcha-related checks |
| `hcaptcha.site_key` | Site key used to decide whether registration must include a CAPTCHA response |
| `hcaptcha.secret` | Secret key setting for server-side verification |

Example SQL:

```sql
UPDATE settings SET value = 'true'            WHERE key = 'hcaptcha.enabled';
UPDATE settings SET value = 'your_site_key'   WHERE key = 'hcaptcha.site_key';
UPDATE settings SET value = 'your_secret_key' WHERE key = 'hcaptcha.secret';
```

## How it works

When a user submits the registration form and `hcaptcha.site_key` is set, the backend requires an `h-captcha-response` field and verifies it against `https://hcaptcha.com/siteverify`. If verification fails, registration is rejected.

<Note>
  The current backend verification path still needs to be aligned with the `hcaptcha.secret` setting. Keep CAPTCHA disabled unless you have tested registration end to end on your instance.
</Note>

## Disabling CAPTCHA

Delete or clear the site key:

```sql
UPDATE settings SET value = '' WHERE key = 'hcaptcha.site_key';
```

With an empty site key, the backend skips hCaptcha verification.
