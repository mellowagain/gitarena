title: "Docker"
description: "Run the current GitArena backend Docker image with PostgreSQL."
---

The Dockerfile in this repository builds the Rust backend binary. It does not build or serve the Next.js frontend.

<Warning>
  Treat the current Docker setup as backend-focused. A full web instance needs a separately deployed frontend that points at the backend API.
</Warning>

## Compose file

```yaml docker-compose.yml
services:
  postgres:
    image: postgres:trixie
    environment:
      POSTGRES_DB: gitarena
      POSTGRES_USER: gitarena
      POSTGRES_PASSWORD: change_me
    volumes:
      - pgdata:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U gitarena"]
      interval: 5s
      timeout: 5s
      retries: 5

  gitarena:
    build: .
    depends_on:
      postgres:
        condition: service_healthy
    environment:
      BIND_ADDRESS: "0.0.0.0:8080"
      DATABASE_URL: "postgres://gitarena:change_me@postgres/gitarena"
    volumes:
      - repos:/repositories
    ports:
      - "127.0.0.1:8080:8080"
      - "2222:2222"

volumes:
  pgdata:
  repos:
```

<Warning>
  Binding to `127.0.0.1:8080` (instead of `0.0.0.0:8080`) means only your reverse proxy can reach GitArena. Do not expose port 8080 directly to the internet — put a reverse proxy in front of it. See the [reverse proxy guide](/self-hosting/reverse-proxy).
</Warning>

## Volumes

| Volume | Purpose |
|--------|---------|
| `pgdata` | PostgreSQL data directory |
| `repos` | Bare git repositories on disk |

The `repos` volume is mounted at `/repositories` inside the container. Set `repositories.base_dir` to `/repositories` before creating repositories:

```bash
docker compose exec postgres psql -U gitarena -d gitarena -c \
  "UPDATE settings SET value = '/repositories' WHERE key = 'repositories.base_dir';"
```

Back up both the database volume and repository volume.

## Database password secrets

The main database pool supports `DATABASE_URL_FILE` and `DATABASE_PASSWORD_FILE`, but the background queue currently requires `DATABASE_URL` directly. Keep the password in `DATABASE_URL` until queue startup supports file-based secrets.

## Frontend deployment

Run the frontend separately from `gitarena-frontend`:

```bash
cd gitarena-frontend
pnpm install
NEXT_PUBLIC_API_URL=http://127.0.0.1:8080 pnpm run build
NEXT_PUBLIC_API_URL=http://127.0.0.1:8080 pnpm run start
```

For local development, use `pnpm run dev`; it listens on port `8321`.

## Upgrading

Rebuild the backend image and restart:

```bash
docker compose build gitarena
docker compose up -d gitarena
```

Migrations run automatically on startup.

## Health check

GitArena exposes a health check endpoint at `/healthz`:

```bash
curl http://localhost:8080/healthz
```

A 200 response means the HTTP server responded. Use `/api/admin/health` from an admin session for component health, including database connectivity.

## Logs

By default, GitArena writes logs to stdout. View them with Docker:

```bash
docker compose logs -f gitarena
```

Set `NO_STDOUT_LOG` to disable stdout logging. Set `DEBUG_FILE_LOG` in non-debug builds to enable rolling file logs.
