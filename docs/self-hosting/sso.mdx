title: "SSO"

GitArena supports OAuth2 single sign-on with GitHub, GitLab, and Bitbucket. Each provider is configured independently through the admin settings.

## GitHub

<Steps>
  <Step title="Create a GitHub OAuth app">
    Go to **GitHub Settings → Developer settings → OAuth Apps → New OAuth App** and fill in:

    - **Application name**: your instance name
    - **Homepage URL**: `https://git.example.com`
    - **Authorization callback URL**: `https://git.example.com/api/sso/github/callback`

    After registering, copy the **Client ID** and generate a **Client secret**.
  </Step>
  <Step title="Configure GitArena">
    Update the settings table, or set these values from the admin panel at `/admin`:

    ```sql
    UPDATE settings SET value = 'true'               WHERE key = 'sso.github.enabled';
    UPDATE settings SET value = 'your_client_id'     WHERE key = 'sso.github.client_id';
    UPDATE settings SET value = 'your_client_secret' WHERE key = 'sso.github.client_secret';
    ```
  </Step>
</Steps>

## GitLab

<Steps>
  <Step title="Create a GitLab OAuth app">
    Go to **GitLab → User Settings → Applications** and fill in:

    - **Name**: your instance name
    - **Redirect URI**: `https://git.example.com/api/sso/gitlab/callback`
    - **Scopes**: `read_user`

    After saving, copy the **Application ID** and **Secret**.
  </Step>
  <Step title="Configure GitArena">
    ```sql
    UPDATE settings SET value = 'true'         WHERE key = 'sso.gitlab.enabled';
    UPDATE settings SET value = 'your_app_id'  WHERE key = 'sso.gitlab.client_id';
    UPDATE settings SET value = 'your_secret'  WHERE key = 'sso.gitlab.client_secret';
    ```
  </Step>
</Steps>

## Bitbucket

<Steps>
  <Step title="Create a Bitbucket OAuth consumer">
    Go to **Bitbucket → Settings → OAuth → Add consumer** and fill in:

    - **Name**: your instance name
    - **Callback URL**: `https://git.example.com/api/sso/bitbucket/callback`
    - **Permissions**: Account → Read

    After saving, copy the **Key** (client ID) and **Secret**.
  </Step>
  <Step title="Configure GitArena">
    ```sql
    UPDATE settings SET value = 'true'       WHERE key = 'sso.bitbucket.enabled';
    UPDATE settings SET value = 'your_key'   WHERE key = 'sso.bitbucket.client_id';
    UPDATE settings SET value = 'your_secret' WHERE key = 'sso.bitbucket.client_secret';
    ```
  </Step>
</Steps>

## How the OAuth flow works

When a user clicks "Sign in with GitHub" (or GitLab/Bitbucket):

1. GitArena redirects the user to the provider's authorization URL.
2. The user approves the OAuth app.
3. The provider redirects back to `/api/sso/{service}/callback` with an authorization code.
4. GitArena exchanges the code for an access token and fetches the user's profile.
5. If an account with the same email exists, the SSO provider is linked to it. Otherwise, a new account is created.
6. A session cookie is set and the user is logged in.

## Disabling a provider

Set the `enabled` key to `false`:

```sql
UPDATE settings SET value = 'false' WHERE key = 'sso.github.enabled';
```

The login button for that provider disappears immediately. Existing accounts linked to that provider are not affected.
