This guide gets your development environment running from scratch. For a broader overview of the development workflow, see the [development setup guide](/development).

## Prerequisites

| Tool | How to install |
|------|---------------|
| Rust (stable) | [rustup.rs](https://rustup.rs) |
| Node.js 18+ | [nodejs.org](https://nodejs.org) or `nvm` |
| pnpm | `npm install -g pnpm` |
| PostgreSQL 14+ | System package manager or Docker |
| sqlx-cli | `cargo install sqlx-cli --no-default-features --features postgres` |

### Use the dev container

The repository includes a `.devcontainer.json` that uses the prebuilt `ghcr.io/mellowagain/gitarena-dev:latest` image. Open the repository in an editor that supports dev containers to get the development toolchain preinstalled: Rust, sqlx-cli, Node.js, and pnpm.

The dev container does not include the services GitArena needs at runtime, such as PostgreSQL, Zoekt, Meilisearch, or S3-compatible object storage. Use the development Compose file below to run them.

### Run the services with Docker Compose

`docker-compose.dev.yml` starts everything except GitArena itself, bound to `127.0.0.1`:

| Service | Port | Purpose |
|---------|------|---------|
| PostgreSQL | `5432` | Database (`gitarena` / `gitarena`) |
| Meilisearch | `7700` | Search |
| Zoekt | `6070` | Code search |
| RustFS | `9000`, console `9001` | S3 object storage (`rustfsadmin` / `rustfsadmin`) |
| Mailpit | SMTP `1025`, UI `8025` | Catches outgoing email |
| OpenObserve | `5080` | Traces, metrics and logs (`admin@gitarena.local` / `gitarena-dev`) |

The backend's `zoekt-git-index` writes the code search index on the host, and the Zoekt container reads it from the same directory. Create it first:

```bash
mkdir -p ~/.local/share/gitarena/zoekt-index
docker compose -f docker-compose.dev.yml up -d
export DATABASE_URL=postgres://gitarena:gitarena@localhost/gitarena
export OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:5080/api/default
export OTEL_EXPORTER_OTLP_HEADERS=Authorization=Basic%20YWRtaW5AZ2l0YXJlbmEubG9jYWw6Z2l0YXJlbmEtZGV2
```

After the backend has started once and created the schema, point its settings at these services:

```bash
docker compose -f docker-compose.dev.yml exec -T postgres psql -U gitarena -d gitarena -v ON_ERROR_STOP=1 < deploy/compose/dev.sql
```

Then restart the backend. Zoekt indexing also needs `zoekt-git-index` on the host (see [search](/self-hosting/search)).

## Getting started

<Steps>
  <Step title="Clone and build">
    ```bash
    git clone https://github.com/mellowagain/gitarena.git
    cd gitarena
    cargo build
    ```

    The first build takes a while — Cargo downloads and compiles all dependencies. Later builds are much faster.
  </Step>

  <Step title="Set up the database">
    Create a development database and export the backend environment variables in your shell:

    ```bash
    createdb gitarena_dev
    ```

    ```bash
    export DATABASE_URL=postgres://your_user@localhost/gitarena_dev
    export BIND_ADDRESS=127.0.0.1:8080
    ```
  </Step>

  <Step title="Install frontend dependencies">
    ```bash
    cd gitarena-frontend
    pnpm install
    ```
  </Step>

  <Step title="Run everything">
    Open two terminals:

    <CodeGroup>
      ```bash Backend
      cargo run -p gitarena
      ```

      ```bash Frontend
      cd gitarena-frontend
      pnpm run dev
      ```

    </CodeGroup>

    Open `http://localhost:8321`. The frontend proxies API calls to the backend on port 8080. Background jobs run inside the backend process.
  </Step>
</Steps>

## Running tests

```bash
# All tests
cargo test

# A specific crate
cargo test -p gitarena

# A specific test by name
cargo test -p gitarena your_test_name
```

## Before submitting a PR

<CodeGroup>
  ```bash Backend
  cargo fmt
  cargo clippy
  ```

  ```bash Frontend
  cd gitarena-frontend
  pnpm run format
  pnpm run lint
  ```
</CodeGroup>

Only fix lint warnings in files you changed — don't clean up pre-existing warnings in unrelated code.
