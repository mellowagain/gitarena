The main `gitarena` crate is an [Actix-Web](https://actix.rs) backend. It handles REST API endpoints, smart HTTP git routes, built-in SSH startup, sessions, migrations, and background queue workers.

## Entry point

`gitarena/src/main.rs` bootstraps the backend:

<Steps>
  <Step title="Load runtime settings">
    The process reads environment variables, opens the PostgreSQL pool, runs embedded migrations, and reads `secret` and `domain` from the settings table.
  </Step>
  <Step title="Start shared services">
    Startup creates the WebAuthn configuration, mail transport, fang queue workers, expiry cron task, and built-in SSH server.
  </Step>
  <Step title="Mount HTTP routes">
    Actix registers API, repository, user, organization, admin, smart HTTP, OpenAPI, RapiDoc, and health routes.
  </Step>
  <Step title="Listen for requests">
    The server binds to `BIND_ADDRESS` and starts accepting HTTP traffic.
  </Step>
</Steps>

## Route layout

Routes live under `gitarena/src/routes/`. They are grouped by domain:

| Directory | Purpose |
|-----------|---------|
| `routes/admin/` | Admin stats, health, and users APIs |
| `routes/organization/` | Organization profile, members, and repositories APIs |
| `routes/repository/` | Repository APIs, pages, smart HTTP, files, commits, stars, imports, forks |
| `routes/user/` | Registration, auth, sessions, emails, SSH keys, SSO, profiles, avatars |
| `routes/proxy/` | Image proxying used by rendered Markdown |

Route handlers use the `gitarena-macros` `#[route(...)]` macro and are registered through the route modules.

## Middleware

| Layer | Purpose |
|-------|---------|
| Request tracing | Adds tracing spans around requests |
| Request metrics | Records HTTP metrics |
| `NormalizePath` | Normalizes trailing slashes |
| `actix-identity` | Cookie-based identity through the `gitarena-auth` cookie |
| Header wrapper | Adds `Access-Control-Allow-Origin: *` to non-`.git` responses and no-cache headers to `.git` responses |
| Error renderer | Converts application errors into JSON, text, git, HTML, or HTMX responses |

The session cookie is configured with `HttpOnly`, `SameSite::Lax`, and a 10-day max age. The `Secure` flag is added when the `domain` setting starts with `https`. Each session maps to a row in the `sessions` table, storing the user ID, IP address, user agent, and timestamps.

## Error handling

GitArena uses two error macros from the `gitarena-macros` crate:

```rust
// Early exit with an HTTP status code and a message shown to the user
die!(BAD_REQUEST, "Repository name cannot be empty");

// Convert a Result error with a status code and user-facing message
some_func().map_err(|_| err!(NOT_FOUND, "Repository not found"))?;
```

For errors that should not expose details to the user, use the standard `anyhow` macros:

```rust
// Results in a 500 Internal Server Error; message goes to the log only
bail!("Unexpected state in import handler");
```

Most return types are `anyhow::Result<impl Responder>`. Actix-Web's error handling converts these to HTTP responses.

## OpenAPI

Routes should be annotated with `#[utoipa::path]` and response types exposed through the API should derive `#[derive(utoipa::ToSchema)]`. Coverage is still being filled in for some older routes.

The OpenAPI spec is generated at startup and served at `/api-docs/openapi.json`. An interactive RapiDoc UI is available at `/rapidoc`.

Example route annotation:

```rust
#[utoipa::path(
    get,
    path = "/api/repos/{namespace}/{repository}",
    responses(
        (status = 200, description = "Repository metadata", body = RepositoryMeta),
        (status = 404, description = "Repository not found")
    )
)]
```

## Config system

Instance configuration is stored in the `settings` table in PostgreSQL. Existing code uses generated config accessors from `gitarena-macros` for typed setting reads.

## Database access

Database access uses `sqlx`. The connection pool is shared across request handlers through Actix-Web's `web::Data`.

```rust
// Example: fetch a user by username
let user = sqlx::query_as!(User, "SELECT * FROM users WHERE username = $1", username)
    .fetch_optional(&pool)
    .await?;
```
