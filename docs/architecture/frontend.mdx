`gitarena-frontend` is a [Next.js](https://nextjs.org) 16 app. It handles the user-facing UI, fetches backend data with SWR, and renders it with Radix UI, shadcn/ui components, and Tailwind CSS v4.

## Tech stack

| Layer | Library |
|-------|---------|
| Framework | Next.js 16, React 19, TypeScript 5 |
| UI primitives | Radix UI (25+ packages) |
| Component library | shadcn/ui (new-york style) |
| Styling | Tailwind CSS v4 |
| Data fetching | SWR |
| Forms | Local React state with SWR mutations; shadcn form helpers are available |
| Icons | lucide-react |
| Themes | CSS variables; `next-themes` provider exists but is not mounted globally |
| Font | Geist (Vercel) |
| Passkeys | @simplewebauthn/browser |
| Markdown | react-markdown + remark-gfm |
| Syntax highlighting | react-syntax-highlighter |

## Data fetching

All data fetching goes through [SWR](https://swr.vercel.app). Never use `fetch` directly in components.

```typescript
// Reading data
const { data, isLoading, error } = useSWR<RepoMeta>(`/api/repos/${user}/${repo}`);

// Mutations
const { trigger } = useSWRMutation("/api/repo", postJsonFetcher);
```

Always use the `{ data, isLoading, error }` return values from SWR — don't manage loading state with `useState` or `!data` checks. This keeps loading skeletons and error states consistent.

Shared fetchers live in `lib/fetchers.ts`. Use one of those before writing a custom fetcher. If the existing fetchers don't cover your use case, add a generalized one there rather than inlining it.

## Component structure

| Path | Purpose |
|------|---------|
| `components/ui/` | shadcn/ui component library |
| `components/top-bar.tsx` | Page header and navigation |
| `components/client-layout.tsx` | Client-side layout wrapper |
| `components/navigation-progress.tsx` | Route transition indicator |
| `components/repo-sidebar.tsx` | Repository sidebar content |
| `components/repo-file-sidebar.tsx` | File tree sidebar |
| `components/language-bar.tsx` | Repository language breakdown |
| `components/markdown-renderer.tsx` | Markdown rendering |
| `components/instance-config-provider.tsx` | Hook-like helper that fetches `GET /api` |

Use components from `components/ui/` for all basic UI elements. They follow the shadcn/ui new-york style with CSS variables for theming.

## Theming

Color tokens are defined as CSS variables in `app/globals.css` using Tailwind CSS v4's CSS-based configuration. A `components/theme-provider.tsx` wrapper exists, but the root layout does not currently mount it globally.

## Instance configuration

The backend exposes public instance metadata through `GET /api`. `components/instance-config-provider.tsx` currently exports a `useInstanceConfig()` helper that calls `useSWR("/api")`; it is not a React context provider.

## Code style rules

- The ESLint `curly` rule is enabled — always use curly braces around `if` statement bodies, even for one-liners.
- Use `pnpm run lint`, not `pnpm lint`.
- Format with `pnpm run format` before committing.
